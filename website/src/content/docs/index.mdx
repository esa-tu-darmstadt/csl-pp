csl++ is a place to develop new language features for CSL and to test them at wafer scale. It extends CSL, so every CSL program is also a csl++ program.

The csl++ compiler `csl-pp` is a drop-in replacement for `cslc` and takes the same command-line arguments. It translates a program to vanilla CSL and then compiles the result with `cslc`, the compiler of the Cerebras SDK.

<Pipeline />

## Language extensions

csl++ currently adds two extensions to CSL. The [Tutorial](tutorial/) introduces them step by step with one small program, and the [Language](language/overview/) section is their reference. The [libraries](libraries/) that come with csl++ are written with them.

<div class="feature">

### Async CSL

A task of vanilla CSL runs to completion, so a sequence of asynchronous fabric operations is written as one task per step, or as a state machine with its values in globals. In csl++, a task can suspend: it ends its current run at `suspend` and continues after it when it is activated again, with its local variables intact.

<Example file="tutorial/4-parallel/src/receiver.csl" region="async" />

An async function is called with `@await` like an ordinary function and returns its result. `@await_parallel` runs several calls at the same time and continues when all of them have returned. A library offers async functions instead of taking a task ID to activate when it is done.

[Async functions and tasks →](language/async/)

</div>

<div class="feature">

### Automatic resource allocation

Vanilla CSL names colors, task IDs and queues by number. The numbers of all modules of a program must be distinct, so the programmer keeps a table of them and passes them into every library. In csl++, a module claims what it needs. A claim at compile time returns a resource that no other claim returns and that memcpy does not use. A claim at runtime takes one of those that are left, and can be released again:

```csl
const c_route: color = @claim_color();
const iq: input_queue = @claim_input_queue();
const task_id: local_task_id = @claim_local_task();
```

A library claims its own resources, so the program imports it without resource parameters, and two libraries, or two instances of one, never collide.

[Claims →](language/resources/)

</div>

## Libraries

Three libraries of the Cerebras SDK benchmarks are ported to csl++ and come with it: [`allreduce`](libraries/allreduce/), a reduction over all PEs; [`stencil_3d_7pts`](libraries/stencil_3d_7pts/), a 7-point stencil product on a 3D grid; and [`collectives_2d`](libraries/collectives_2d/), broadcast, scatter, gather and reduce along rows or columns. They offer async functions and claim their resources.

## Tools

`csl-pp` writes readable CSL, with one file per distinct PE program. Its frontend also drives `csl-lsp-server`, a language server with diagnostics, hover, completion and go-to-definition for CSL and csl++ in [VS Code](tools/vscode/). [simtracer](tools/simtracer/) shows flamegraphs and instruction traces of simulator runs of any CSL program, and keeps the call stacks of async tasks intact across `suspend`.

[csl-pp →](tools/csl-pp/)

## Get started

<ol class="steps">
<li>

Install `csl-pp` from PyPI, next to the Cerebras SDK. [Installation →](start/installation/)

```bash
pipx install csl-pp
```

</li>
<li>

Compile a CSL program with it: replace `cslc` with `csl-pp` in the command of any SDK example. The arguments stay the same. [Quickstart →](start/quickstart/)

```bash
csl-pp ./layout.csl --arch=wse3 --fabric-dims=8,3 --fabric-offsets=4,1 -o out --memcpy --channels=1
```

</li>
<li>

Follow the tutorial, which introduces `suspend`, async functions, claims and parallel calls. [Tutorial →](tutorial/)

</li>
</ol>

## Development

csl++ is developed by the [Embedded Systems and Applications Group](https://www.esa.informatik.tu-darmstadt.de) at the Technical University of Darmstadt as a research project on programming the Cerebras Wafer-Scale Engine. It is not a product of Cerebras Systems; CSL, `cslc` and the SDK are. The code is open source, and new language features, library ports, bug reports and fixes are welcome. [Contributing →](project/contributing/)

The paper on the async extension and its stackful lowering, *Structured Coroutines for the Wafer-Scale Engine*, has been accepted at CGO 2027 in Salt Lake City. It is not published yet; see [About](project/about/#publication) for how to cite it until then.
