This guide converts CSL code in which asynchronous operations continue in other tasks into an async task. [Step 1 of the tutorial](../../tutorial/1-solver/) shows the result for the conjugate gradient solver of the SDK benchmarks.

## Steps

1. Find the sequence. Collect the tasks that continue each other through `.activate` or `.unblock`, or the arms of a state machine and the order in which its state variable selects them. Together they form one sequence of steps.

2. Write the sequence as one async task. Declare an `async task` that contains the steps in order. After each asynchronous operation that used to activate the next task, activate the current task instead and suspend:

   ```csl
   @fadds(x_dsd, x_dsd, in_dsd, .{ .async = true, .activate = @current_task() });
   suspend;
   ```

   The code of the next task follows the `suspend`. Bind the async task with `@bind_local_task` and remove the tasks it replaces.

3. Replace the state variable with control flow. Transitions that set the state back to an earlier step become loops; transitions that depend on a condition become `if` statements.

4. Move values into local variables. Globals that only carry values from one step to the next can be local variables of the async task. Local variables keep their values and addresses across `suspend`.

5. Turn helper functions into async functions. A function that starts an operation and takes the task to continue with as a parameter becomes an `async fn` that activates `@current_task()` and suspends. Callers call it with `@await`.

6. Initialize the runtime. Call `@coro_runtime_init()` once before the first async task is activated, usually in the function the host launches.

7. Claim resources. Replace fixed colors, task IDs and queues with `@claim_color()`, `@claim_local_task()`, `@claim_input_queue()` and so on. See [Resource allocation](../../language/resources/).

## Libraries with callbacks

A library function that takes a task to activate on completion can be used from async code without changing the library: pass `@current_task()` and suspend.

```csl
callback_lib.start_transfer(&buffer, @current_task());
suspend;
```

## Things to check

- A suspended task resumes on any activation. If other code activates the same task ID, for example a library that was given the ID for another purpose, the task resumes too early. Give such code its own task ID.
- Operations that end with `.unblock` instead of `.activate` do not resume a suspended task. Use `.activate = @current_task()`.
- `sys_mod.unblock_cmd_stream()` returns control to the host. Call it after the last step of the async task, as the last task of the chain did before.
- Two operations that run at the same time must not share a queue or a microthread, as in CSL. With `@await_parallel`, this applies to the operations of all its calls.
