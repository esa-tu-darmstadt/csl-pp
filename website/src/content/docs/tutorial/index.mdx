The tutorial introduces the language extensions of csl++ with one small program, which changes from step to step. It assumes that you know CSL as taught in the [tutorials of the Cerebras SDK](https://sdk.cerebras.ai): tasks, DSDs, colors and routes, and memcpy.

## Program

Three PEs form a row. Each of the two outer PEs holds a value and sends it to the middle PE. The middle PE receives the two values and adds them.

```
    PE 0                    PE 1                    PE 2
 sender.csl  ─────────►  receiver.csl  ◄─────────  sender.csl
             west_color                east_color
```

The outer PEs run `sender.csl`, which is vanilla CSL. When the host calls `compute`, the PE sends its value `x` to the middle PE:

<Example file="tutorial/1-suspend/src/sender.csl" region="compute" />

The middle PE runs `receiver.csl`. It has one input queue and one fabric input DSD for each neighbor:

<Example file="tutorial/1-suspend/src/receiver.csl" region="queues" />

The tutorial is about the rest of this file: the code that receives the two values and stores their sum. The layout file routes one color from each outer PE to the middle PE. The host program writes a value to each outer PE, calls `compute` on all PEs, and reads the sum from the middle PE.

## Running a step

Every step has a complete program in the csl++ repository, in `website/examples/tutorial`. With `csl-pp` and the Cerebras SDK on your `PATH`, as described in [Installation](../start/installation/), clone the repository and run the script of a step:

```bash
git clone https://github.com/esa-tu-darmstadt/csl-pp.git
cd csl-pp/website/examples/tutorial/1-suspend
./commands_wse3.sh
```

The script compiles the program for WSE-3 and runs it on the simulator of the SDK. `commands_wse2.sh` does the same for WSE-2.

<Example file="tutorial/1-suspend/commands_wse3.sh" />

`csl-pp` takes the arguments of `cslc`. The host program prints the two values and the sum that it read from the middle PE:

```
1.5 + 2.25 = 3.75
SUCCESS!
```

## Steps

1. [Suspending a task](1-suspend/): a task waits for an operation with `suspend`.
2. [Async functions](2-await/): the wait becomes a function that is called with `@await`.
3. [Claiming resources](3-claims/): the program claims its colors, queues and task ID instead of choosing numbers.
4. [Parallel calls](4-parallel/): `@await_parallel` receives both values at the same time.
